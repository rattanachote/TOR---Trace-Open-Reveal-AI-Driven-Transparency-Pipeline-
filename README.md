# TOR — สำรวจข้อมูลจัดซื้อจัดจ้างทั้งหมดในเครื่อง

เปิด Docker Desktop แล้วดับเบิลคลิก **Start Web App.cmd** จากนั้นเปิด http://127.0.0.1:8770

ใช้ฐานข้อมูล `../output/linked-data/procurement.sqlite3` ไม่ต้องติดตั้งระบบฐานข้อมูลเพิ่มเติม เซิร์ฟเวอร์เปิดเฉพาะในเครื่องนี้ และให้บริการเฉพาะหน้าเว็บกับ API ไม่เปิดไฟล์ฐานข้อมูลให้ดาวน์โหลดผ่านเว็บ

## ติดตั้งจาก GitHub

โค้ดอยู่ใน Git แต่ **ข้อมูลไม่อยู่** (ฐานข้อมูลจัดซื้อจัดจ้าง 52 GB, ไฟล์ต้นฉบับ e-GP, ทะเบียน DBD, `.env`, `backups/`, `logs/`) หลัง clone จึงต้องเลือกว่าจะใช้งานระดับไหน

### ต้องมี

- **Git** และ **Python 3.12** (ทดสอบกับรุ่นนี้ ใช้ไลบรารีมาตรฐาน ไดรเวอร์ PostgreSQL `pg8000` อยู่ใน `vendor/` แล้ว ไม่ต้อง `pip install`)
- **Docker Desktop** สำหรับฐานข้อมูลบัญชีผู้ใช้ (PostgreSQL) ไม่ต้องมีเมื่อแค่เปิดโหมดตัวอย่าง

### เลือกระดับการใช้งาน

| อยากทำอะไร | ต้องมีอะไรเพิ่ม |
|---|---|
| ดูหน้าตาและแก้หน้าเว็บ (`frontend/`) | ไม่ต้องมีอะไร: เปิดไฟล์ `frontend/index.html` ตรงจากโฟลเดอร์ ได้ “โหมดตัวอย่าง” ที่ใช้โครงการตัวอย่าง 5 รายการ ไม่ต้องเปิดเซิร์ฟเวอร์และไม่ต้องล็อกอิน |
| ล็อกอิน บทบาท คิวตรวจทาน เรื่องที่บันทึก และเผยแพร่ | Docker เท่านั้น เปิดเซิร์ฟเวอร์ตามขั้นตอนด้านล่าง หน้าที่ค้นข้อมูลจัดซื้อจัดจ้างจะแจ้งข้อผิดพลาดเพราะยังไม่มีฐานข้อมูล |
| ค้นหา ดูแผนผัง และข้อมูลจริงทั้งชุด | ไฟล์ `procurement.sqlite3` |
| หน้าภาพรวมและตัวชี้วัด | `analytics.sqlite3` (ไม่มี: หน้านี้แจ้งว่ายังไม่ได้สร้าง) |
| เส้นผู้เสนอราคาเพิ่ม คิวคนชื่อซ้ำ แยกหน่วยงานชื่อซ้ำ | `identity.sqlite3` (ไม่มี: แอปทำงานเหมือนเดิมโดยไม่มีส่วนนี้) |

### โครงสร้างโฟลเดอร์ที่โค้ดคาดหวัง

โค้ดหาข้อมูลจาก **โฟลเดอร์แม่ของโฟลเดอร์ที่ clone** ดังนั้นต้องวางให้ตรงกันแบบนี้ (ชื่อโฟลเดอร์ที่ clone ตั้งอะไรก็ได้)

```
<โฟลเดอร์โปรเจกต์>/
├── <โฟลเดอร์ที่ clone มา>/          โค้ดนี้ (ในเครื่องผู้พัฒนาตั้งชื่อว่า "Web App")
├── output/linked-data/              procurement.sqlite3, analytics.sqlite3, identity.sqlite3
├── Data.go.th/Contract/             ต้นฉบับ YYYY-egp-contract.zip            (ต้องมีเมื่อสร้างฐานข้อมูลเอง)
├── Data.go.th/Submit (รายชื่อผู้เสนอราคา)/   YYYY-egp-contract-submit.zip      (ต้องมีเมื่อสร้างฐานข้อมูลเอง)
└── YYYY-MM-DD/<เลขนิติบุคคล>/<รหัส>/company.json   ภาพทะเบียน DBD         (ต้องมีเมื่อสร้างฐานข้อมูลเอง)
```

### เปิดเซิร์ฟเวอร์ครั้งแรก

ใน Windows ดับเบิลคลิก **Start Web App.cmd** (เปิด Docker สร้าง `.env` และเปิดเซิร์ฟเวอร์ให้) หรือทำเองจากโฟลเดอร์ที่ clone:

```
python backend/server.py --setup                                    # สร้าง .env ที่มีรหัสผ่านสุ่ม (ทำครั้งเดียว)
docker compose -f docker/docker-compose.yml --env-file .env up -d --wait
python backend/server.py --port 8770
```

เปิด http://127.0.0.1:8770 ผู้ดูแลคนแรกคือ `admin` รหัสผ่านอยู่ใน `.env` (`TOR_ADMIN_PASSWORD`) และระบบบังคับให้เปลี่ยนตอนเข้าครั้งแรก ตรวจว่าพร้อมที่ http://127.0.0.1:8770/api/health ซึ่งจะบอกว่า `procurement_db`, `accounts_db`, `analytics_db` เป็น `ok` หรือ `missing`

`.env` สร้างขึ้นในเครื่องของแต่ละคน **ห้าม commit** และแต่ละเครื่องมีบัญชีผู้ใช้ของตัวเอง ไม่ใช้ร่วมกัน

### ได้ไฟล์ฐานข้อมูลมาอย่างไร

1. **ขอไฟล์จากคนที่สร้างไว้แล้ว** (ทางที่ง่ายที่สุด) วาง `procurement.sqlite3` และไฟล์อื่นที่ได้รับที่ `output/linked-data/` ตามโครงสร้างด้านบน
2. **สร้างเอง** จากไฟล์ต้นฉบับ (ฐานข้อมูลที่ได้ราว 55 GB บวกไฟล์ต้นฉบับ e-GP 3.5 GB และทะเบียน DBD และต้องเผื่อพื้นที่ชั่วคราวระหว่างสร้าง ใช้เวลานาน ขึ้นกับเครื่อง) รันจากโฟลเดอร์ที่ clone ตามลำดับ

   ```
   python pipeline/link_all.py           # นำเข้า e-GP + ทะเบียน DBD และเชื่อมข้อมูลรอบแรก สร้าง procurement.sqlite3
   python pipeline/relink_identity.py    # เชื่อมรอบสอง สร้าง identity.sqlite3 (ราว 6 นาที)
   python pipeline/build_analytics.py    # ภาพรวมและตัวชี้วัด สร้าง analytics.sqlite3 (ราว 18 นาที)
   ```

   ไฟล์ e-GP ดาวน์โหลดจาก Data.go.th (ชุดข้อมูลสัญญาและรายชื่อผู้เสนอราคา) ส่วนข้อมูลทะเบียน DBD ต้องดึงด้วยเครื่องมือดึงข้อมูลของผู้พัฒนา ซึ่งไม่ได้อยู่ใน repo นี้ รายชื่อบริษัทที่ควรดึงก่อนอยู่ที่ [docs/dbd-fetch-worklist.csv](docs/dbd-fetch-worklist.csv)

### ทดสอบ

```
python -m unittest discover -s tests -p "test_unit.py"      # ไม่ต้องมีข้อมูลหรือ Docker
python -m unittest discover -s tests -p "test_namekey.py"
python -m unittest discover -s tests -p "test_identity.py"
python -m unittest discover -s tests -p "test_api.py"       # ต้องมี Docker และ procurement.sqlite3 (ใช้ฐานบัญชีแยกชื่อ tor_test)
```

ถ้าไม่มี Docker หรือฐานข้อมูล `test_api.py` จะข้ามตัวเอง ส่วนเคสที่ใช้ `identity.sqlite3` จะข้ามเมื่อไม่มีไฟล์

## บัญชีผู้ใช้และบทบาท

ต้องเข้าสู่ระบบก่อนดูข้อมูล บัญชี บทบาท เซสชัน ผลตรวจทาน และประวัติการทำงานเก็บใน PostgreSQL ที่รันด้วย Docker (`docker/docker-compose.yml`, container `tor-auth-db`, พอร์ต 127.0.0.1:5433) ส่วนข้อมูลจัดซื้อจัดจ้างยังอยู่ใน SQLite เดิม

- ครั้งแรก `Start Web App.cmd` จะรัน `python backend/server.py --setup` เพื่อสร้าง `.env` ที่มีรหัสผ่านฐานข้อมูลและรหัสผ่านผู้ดูแลคนแรกแบบสุ่ม แล้วรัน `docker compose -f docker/docker-compose.yml --env-file .env up -d --wait` ก่อนเปิดเซิร์ฟเวอร์
- ผู้ดูแลคนแรกคือ `admin` รหัสผ่านอยู่ที่ `TOR_ADMIN_PASSWORD` ใน `.env` ควรเปลี่ยนรหัสผ่านหลังเข้าสู่ระบบครั้งแรก (ปุ่มรหัสผ่านที่มุมซ้ายล่าง)
- **ผู้ใช้งาน (user)**: สมัครสมาชิกเองได้ ดูข้อมูล รายละเอียด แผนผัง หลักฐาน และส่งออกได้ แต่ยืนยันข้อมูลก่อนเผยแพร่ไม่ได้ เห็นผลตรวจทานแบบอ่านอย่างเดียว
- **ผู้ดูแลระบบ (admin)**: ทำได้ทุกอย่าง รวมถึงยืนยัน/ปฏิเสธข้อมูล สร้างผู้ใช้ ตั้งรหัสผ่านใหม่ ระงับบัญชี เปลี่ยนบทบาท และสร้างบทบาทใหม่ที่เลือกสิทธิ์เองได้ (`data.view`, `data.export`, `review.confirm`, `users.manage`, `roles.manage`)
- บทบาท admin มีทุกสิทธิ์เสมอ และระบบไม่ยอมให้เหลือผู้ใช้ที่จัดการผู้ใช้และบทบาทได้เป็นศูนย์
- รหัสผ่านเก็บแบบ scrypt เซสชันเป็น cookie HttpOnly + SameSite=Strict อายุ 7 วัน คำขอ POST ต้องเป็น JSON จากเว็บเดียวกัน เข้าสู่ระบบผิดเกิน 8 ครั้งใน 10 นาทีจะถูกพักชั่วคราว
- ไดรเวอร์ PostgreSQL (`pg8000`, pure Python) อยู่ใน `vendor/`
- หยุดฐานข้อมูลบัญชี: `docker compose -f docker/docker-compose.yml stop` · ข้อมูลอยู่ใน volume `tor_tor-auth-data` (`down -v` จะลบบัญชีทั้งหมด)

## ฟังก์ชันที่เพิ่มตาม REVIEW-AND-ROADMAP (31 ต.ค. 2569)

- **ค้นชื่อไม่ขึ้นกับช่องว่าง** — `นาย ยงยุทธ ปวิตรปก`, `นายยงยุทธ ปวิตรปก` และชื่อที่ทะเบียนเว้นสองช่องหาเจอเหมือนกัน คำนำหน้าและคำว่า บริษัท/จำกัด ถูกตัดออกจากคำค้น
- **ความปลอดภัย** — ปิดการแสดงรายการไฟล์ในโฟลเดอร์ เพิ่ม Content-Security-Policy, X-Frame-Options และ header อื่น ซ่อนชื่อซอฟต์แวร์เซิร์ฟเวอร์ จำกัดการเข้าสู่ระบบผิดต่อ IP+ชื่อผู้ใช้ (8 ครั้ง) และต่อ IP (30 ครั้ง) ใน 10 นาที จำกัด 300 คำขอ API ต่อนาทีต่อบัญชี บันทึกการเข้าใช้ใน `logs/access.log`
- **บังคับเปลี่ยนรหัสผ่าน** — บัญชีผู้ดูแลคนแรก บัญชีที่ผู้ดูแลสร้าง และรหัสที่ผู้ดูแลตั้งใหม่ ต้องเปลี่ยนรหัสก่อนใช้งาน
- **บทบาทผู้ตรวจทาน (reviewer)** — ดู ส่งออก และยืนยันข้อมูล/เผยแพร่ได้ โดยไม่ต้องมีสิทธิ์จัดการผู้ใช้
- **ตรวจทาน** — ใส่หมายเหตุประกอบผลตรวจได้ ยืนยันเส้น “หน่วยงานเจ้าของโครงการ” เป็นกลุ่มต่อหน่วยงาน
- **เรื่องที่บันทึก และการเผยแพร่** — บันทึกแผนผัง (จุดเริ่มต้น ความลึก จุดที่ขยาย) พร้อมคำอธิบาย ส่งให้ผู้ตรวจทาน ผู้มีสิทธิ์ `review.confirm` ดูตัวอย่าง เผยแพร่ ส่งกลับ หรือถอนการเผยแพร่ได้ ตอนเผยแพร่เซิร์ฟเวอร์สร้างแผนผังใหม่จากฐานข้อมูล และเก็บเฉพาะเส้นที่เชื่อมด้วยตัวระบุหรือผ่านการยืนยัน
- **หน้าสาธารณะ** (`#public`, `#case=…`, `#about`) — ไม่ต้องเข้าสู่ระบบ แสดงเฉพาะเรื่องที่เผยแพร่ ดาวน์โหลดหลักฐานที่อ้างถึงได้ มีหน้าวิธีการและข้อจำกัด และแบบฟอร์มแจ้งแก้ไขข้อมูลที่ผู้ตรวจทานจัดการได้ในแท็บ “คำขอแก้ไข”
- **ภาพรวมและตัวชี้วัด** — มูลค่า/จำนวนสัญญารายปี วิธีจัดซื้อ จังหวัด หน่วยงานและผู้รับจ้างรายใหญ่ ตัวชี้วัดทั้งชุดข้อมูล 5 แบบ (การกระจุกตัว HHI, สัดส่วนวิธีเฉพาะเจาะจง, ราคาเท่ากับวงเงิน, ผู้เสนอราคารายเดียว, คู่ผู้เสนอราคาที่พบบ่อยและมีผู้เกี่ยวข้องร่วม) โปรไฟล์หน่วยงาน/ผู้รับจ้าง และตัวชี้วัดในรายละเอียดของจุดในแผนผัง ต้องรัน `python pipeline/build_analytics.py` หลังนำเข้าข้อมูล
- **แผนผัง** — ตัวกรอง “เฉพาะเส้นที่ยืนยันแล้ว” และช่วงปีงบประมาณ, หาเส้นทางระหว่างสองจุดในแผนผังที่โหลด

  - เส้นผู้เสนอราคา 406,316 แถว (ตัวระบุจาก 56.1% เป็น 62.8% ของ 6.06 ล้านแถว) ทุกเส้นติดป้าย “ยังไม่ยืนยัน” ความเชื่อมั่นต่ำ ผู้ตรวจทานต้องยืนยันก่อนเผยแพร่
  - กฎเทียบชื่อใหม่ (เลขไทย, บ./บจก./หจก., สำนักงานใหญ่, สาขา) ที่เก็บประเภทนิติบุคคลไว้เป็นป้าย ไม่ตัดทิ้ง

## การใช้งาน

- ค้นรหัสโครงการ 11 หลัก ชื่อนิติบุคคล ชื่อโครงการ หรือชื่อหน่วยงาน
- ดูรายการโครงการ บริษัทในทะเบียน ผู้เกี่ยวข้อง และแถวข้อมูลที่ต้องทบทวนจากเมนูด้านซ้าย
- ผลค้นหาแบ่งหน้า กดดูกราฟเพื่อโหลดเฉพาะโครงการที่เลือก
- เลือกนิติบุคคลแล้วดูโครงการทั้งหมดของนิติบุคคลนั้น
- เลือกผู้เกี่ยวข้องแล้วดูบริษัทอื่นที่เชื่อมผ่านตัวระบุเดียวกัน
- สลับมุมมองเครือข่าย/ตามปีงบประมาณ และเลือกความลึก 1–3 ชั้นกับจำนวนกิ่งต่อจุดได้ทุกหมวด
- ชี้จุดเพื่อเน้นเส้นที่ต่ออยู่ คลิกจุดเพื่อดูความสัมพันธ์และหลักฐานต้นทาง
- กรองปีโครงการ บริษัทที่มีสัญญา ประเภทผู้เกี่ยวข้อง และจำนวนแถวของหน่วยงาน
- ส่งออกกราฟเป็น SVG/PNG หรือส่งออกข้อมูลเป็น JSON พร้อมหลักฐาน
- ดับเบิลคลิกจุดหรือกด **ขยาย** เพื่อดึงความสัมพันธ์ของจุดนั้นมารวมในแผนผังเดิม กด **ตั้งเป็นศูนย์กลาง** เพื่อเริ่มแผนผังใหม่จากจุดนั้น
- มุมมอง **ตามปีงบประมาณ** วางโครงการตามปีและแยกแถวหน่วยงาน/โครงการ/ผู้รับจ้าง/ผู้เกี่ยวข้อง
- แท็บ **ข้อสังเกต** คำนวณรูปแบบที่ควรตรวจจากจุดที่โหลดอยู่ เช่น ผู้เสนอราคาในโครงการเดียวกันมีผู้เกี่ยวข้องร่วมกัน หรือบุคคลเดียวกันเกี่ยวข้องกับหลายบริษัทที่ได้งานจากหน่วยงานเดียวกัน ข้อสังเกตไม่ใช่ข้อสรุป
- **คิวตรวจทาน** แสดงเส้นที่เชื่อมด้วยชื่อหรือกลุ่มชื่อ ผู้ตรวจทานกดถูกต้อง/ไม่ถูกต้องได้ ผลเก็บใน localStorage ของเบราว์เซอร์และรวมอยู่ในไฟล์ JSON ที่ส่งออก
- ส่วน **แหล่งข้อมูล** ของทุกจุดและทุกเส้นมีลิงก์ตรวจหลักฐาน: **ดาวน์โหลดแถวต้นทาง (CSV)** คัดลอกบรรทัดจากไฟล์ CSV ใน ZIP ต้นฉบับโดยไม่แก้เนื้อหา (เพิ่ม BOM ให้ Excel อ่านภาษาไทย) และ **ดูแถวในไฟล์ต้นฉบับ** แสดงเลขบรรทัด CRC32 ของไฟล์ และค่าทุกคอลัมน์ ข้อมูลทะเบียนเปิด `profile.pdf`, `raw.json`, `company.json` และ `manifest.json` (มี SHA-256) จากโฟลเดอร์ DBD ที่เก็บไว้
- API หลักฐาน: `/api/evidence/row?archive=&member=&seq=&format=csv|json` และ `/api/evidence/dbd?source=&file=profile.pdf|raw.json|company.json|manifest.json` ให้บริการเฉพาะไฟล์ที่ฐานข้อมูลอ้างถึงและอยู่ในโฟลเดอร์โครงการเท่านั้น
- ลิงก์ในแถบที่อยู่ (`#g=company:0102504000650&d=2&b=8`) เปิดแผนผังเดิมซ้ำได้
- การค้นหาข้อความอิสระที่ต้องสแกนระเบียนจำนวนมากถูกหยุดที่ 12 วินาที และแจ้งให้ใช้คำค้นที่เจาะจงขึ้น
- ตัวอย่าง 5 โครงการเดิมยังเป็นจุดเริ่มต้นได้ ถ้าเปิด `frontend/index.html` โดยตรงโดยไม่ใช้เซิร์ฟเวอร์จะเป็นโหมดตัวอย่างเท่านั้น

## ข้อมูลและการตีความ

อ่าน CSV สัญญาทุกไฟล์ปี 2565–2569 และ CSV ผู้เสนอราคาทุกไฟล์ที่มีอยู่ปี 2566–2569 รวมทะเบียนในโฟลเดอร์วันที่ ตรวจ ZIP สำรองและไม่โหลดสำเนาซ้ำ

ทุกแถวเก็บ ZIP ไฟล์สมาชิก และคอลัมน์ลำดับ แถวที่จำนวนช่องไม่ตรงหัวตารางหรือรหัสโครงการไม่สมบูรณ์แยกไว้ในตาราง rejected รหัสโครงการซ้ำอาจเป็นหลายสัญญาหรือหลายภาพข้อมูล จึงไม่ตีความว่าเป็นหลายโครงการ กราฟยุบแถวที่เนื้อหาตรงกันแต่ยังเก็บแถวต้นทางในฐานข้อมูล

เลขทะเบียนตรง DBD ใช้เชื่อมนิติบุคคล ชื่อตรงผู้ชนะในโครงการเดียวกันใช้เชื่อมรหัสพร้อมระบุวิธีจับคู่ ชื่อตรงทะเบียนหนึ่งรายการเพียงอย่างเดียวยังเป็นผู้สมัครจับคู่ที่ไม่ยืนยัน บุคคลที่ไม่มีตัวระบุไม่รวมข้ามบริษัทด้วยชื่ออย่างเดียว เลขบุคคลใช้แฮชภายใน ไม่ส่งเลขจริงไปแสดงในเว็บ

ภาพทะเบียนเดือนกันยายน 2569 ไม่ยืนยันบทบาท ณ วันประมูล เงื่อนไขลงนามเก็บเป็นข้อความต้นทาง ไม่สร้างเส้นเชื่อมจากข้อความอัตโนมัติ ผู้เสนอราคาปีเก่ามีน้อยมากในชุดไฟล์ ต้องดูความครอบคลุมก่อนสรุปการแข่งขัน

## ขอบเขตหน้าจอ

- รายการแบ่งหน้าตามระเบียนต้นทางไม่เกิน 30 แถว และยุบโครงการซ้ำในแต่ละหน้า โครงการที่มีหลายสัญญาอาจปรากฏอีกหน้า
- กราฟแบบเดิมของโครงการโหลดสูงสุด 2,000 แถวสัญญาและ 2,000 แถวผู้เสนอราคาต่อโครงการ พร้อมสถานะ truncated เมื่อมีมากกว่า
- กราฟหลายชั้นจำกัดกิ่งต่อจุด 3–48 รายการ และจำกัดทั้งกราฟ 48/110/180 จุดตามระดับ 1/2/3 เพื่อไม่ให้คำขอเดียวกวาดข้อมูลหลายล้านแถว ส่วนที่ตัดออกแสดงใน `coverage.omitted`
- แผนที่เครือข่ายแสดงเฉพาะจุดที่เชื่อมถึงจุดตั้งต้น กรองจุดที่ไม่มีเส้นทางออก และแสดงเส้นทั้งหมดระหว่างจุดที่มองเห็น โดยเริ่มจากขอบเขตที่อ่านได้ก่อน; ปุ่ม “ทุกจุด” ใช้ขยายรายการที่เหลือ
- ยอดเงินในรายละเอียดเป็นยอดระเบียนสัญญาที่เลือก ไม่ใช่ยอดรวมหลายสัญญาหรือยอดจ่ายจริง

ใช้ Python 3 จากโฟลเดอร์ `Web App`: `python backend/server.py --port 8766` (ต้องเปิดฐานข้อมูลบัญชีใน Docker ก่อน)

Python มาตรฐานเพียงพอสำหรับเซิร์ฟเวอร์และ link_all.py ส่วน pipeline/bulk_import.py ใช้ orjson ใน vendor/ เพื่อเร่งการอ่านเมื่อมี และใช้ Python มาตรฐานแทนได้

จุดบันทึกใช้กับไฟล์ต้นทางชุดเดิมที่ยังไม่เปลี่ยน หากเปลี่ยนเนื้อหาไฟล์ที่ใช้ชื่อเดิม ต้องสร้างฐานข้อมูลชุดใหม่หรือเพิ่มกลไกตรวจเวอร์ชันก่อนนำเข้า ไม่ใช้จุดบันทึกเก่าแทนการตรวจไฟล์ที่อัปเดต

ไฟล์ต้นทางไม่ถูกแก้ไข Google Fonts ใช้เพื่อรูปแบบตัวอักษร หากออฟไลน์จะใช้ Tahoma แทน


## มุมมองรายการและกราฟ

เลือกหมวดโครงการ บริษัท/นิติบุคคล ผู้เกี่ยวข้อง หรือหน่วยงาน แล้วใช้ปุ่ม **รายการ / กราฟ** ด้านบน ทุกหมวดมีจุดศูนย์กลางของตัวเอง เลือกข้อมูลจากผลค้นหาหน้าปัจจุบัน หรือกดตั้งจุดที่เลือกเป็นศูนย์กลางจากรายละเอียดด้านขวาได้

เมื่ออยู่ในกราฟ เลือกระดับ **ภาพรวม / เชิงลึก / ละเอียดสุด** เพื่อขยาย 1–3 ชั้น ตัวอย่างเช่น บุคคล → บริษัทในทะเบียน → โครงการของบริษัท → หน่วยงาน ผู้ชนะ และผู้เสนอราคาร่วมโครงการ แต่ละเส้นมีวิธีเชื่อม ระดับความเชื่อมั่น ช่วงเวลา และหลักฐานต้นทาง ปุ่ม **แสดงกิ่งเพิ่ม** เพิ่มจำนวนความสัมพันธ์ต่อจุดโดยยังคงเพดานความปลอดภัยของกราฟ

กราฟแสดงเส้นทางหลักเป็นต้นไม้จากจุดตั้งต้นเพื่อลดเส้นไขว้ ตัวนับแสดงจำนวนจุด/เส้นที่เห็นเทียบกับข้อมูลที่โหลดในกราฟ ปุ่ม **ทุกจุด N** เปิดจุดที่ถูกย่อ และ **เส้นไขว้ N** เปิดเส้นอื่นระหว่างจุดที่แสดง การแตะจุดจะแสดงเฉพาะเส้นที่ต่อกับจุดนั้นโดยไม่ย้ายตำแหน่ง; ปุ่ม **ดูทุกเส้น +N** เปิดกลับไปดูทั้งหมด ปุ่ม **แสดงกิ่งเพิ่ม** โหลดข้อมูลต่อจุดได้ถึง 48 รายการ โดยกราฟยังมีเพดานจุด 48/110/180 ตามระดับ และแสดง `coverage.omitted` หากยังมีข้อมูลอยู่นอกขอบเขตที่โหลด

หมวดหน่วยงานจัดกลุ่มด้วยชื่อที่ตรงกันเท่านั้น ยังไม่ยืนยันรหัสหน่วยงานทางการ ใช้ agency_catalog และดัชนีที่สร้างด้วย `python pipeline/prepare_graph_views.py` หลังนำเข้าข้อมูล ไม่แก้ไขไฟล์ต้นทาง

API กราฟหลายชั้น: `/api/entity-graph?kind=project|company|person|agency&key=...&limit=6&depth=1|2|3` โดย project ใช้รหัสโครงการ company ใช้เลขทะเบียน person ใช้ entity_key และ agency ใช้ชื่อกลุ่มตรงตามรายการ
